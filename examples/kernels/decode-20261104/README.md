# Decode-path study

Measurements behind the PowerVR decode patch ([write-up](../../../docs/decode.md)), taken on the Pixel 11 Pro Debian VM on 2026-11-04 JST in one VM boot (`59b05043-d0ba-4add-8024-25975af6deff`). The end-to-end A/B on the final runtime is in [`../../inference/decode-study/`](../../inference/decode-study/); this directory holds the probes and the experimental-runtime runs that located the costs.

## Files

- `probes/`: [`guest/probes/dispatch_probe.c`](../../../guest/probes/dispatch_probe.c) and [`submit_probe.c`](../../../guest/probes/submit_probe.c), plain Vulkan on the same device, with the shaders in [`guest/shaders/bench/`](../../../guest/shaders/bench/). The sources are the last versions: `dispatch_probe.c` now runs only the tests of `dispatch-probe-barriers2.jsonl` (earlier test lists in its `main()` produced `dispatch-probe-1.jsonl` and `dispatch-probe-barriers.jsonl`), and `submit_probe.c` no longer prints the 20 warm-up rows that open `submit-probe-1.jsonl`.
  - `dispatch-probe-1.jsonl`: GPU time per small dispatch, as the marginal of 200 against 40 dispatches in one command buffer, for pipeline and descriptor-set changes, push-constant size and timestamps.
  - `dispatch-probe-barriers.jsonl`, `dispatch-probe-barriers2.jsonl`: the same, by barrier type. `ggml_barrier` is the barrier `ggml_vk_sync_buffers` records (compute and transfer stages on both sides, all four access bits). The second file splits it into its parts (`c_to_ct`: transfer added to the destination stage; `ct_to_c`: to the source stage). Repeated rows (`mem_compute`, `ggml_barrier`, `sync2_compute`) show the run-to-run spread.
  - `submit-probe-1.jsonl`: round trip of one trivial submission, chains of 1 to 16 submissions, the same work in one or many submissions, and completion waits. `completion_wait.empty_submit_fence_us` is a fence passed to `vkQueueSubmit` with no batches after 6.8 ms of submitted work: it signals after about 0.15 ms.
  - `probe-mem.jsonl`: the trivial round trip with extra allocations in each memory type (types are listed in the [write-up](../../../docs/decode.md)).
- `host/`: [`guest/probes/vkshim.c`](../../../guest/probes/vkshim.c) wrapped around `llama-bench` on the r3 runtime (u8 kernel on, split output, queue wait, one CPU thread).
  - `shim-plain-{32,160}.json`: call counts and total nanoseconds per Vulkan entry point for 32- and 160-token runs. The difference divided by 128 is the steady per-token cost.
  - `trace-plain-160.txt`: every wrapped call (start ns, duration ns, name, argument) for three tokens.
  - `gshim-plain-*.json`, `gtrace-gpu-plain-160.txt`: the same with a timestamp at the start and end of every command buffer. Each trace line is the submission's CPU time, GPU start and end ticks (26.0417 ns), and the number of dispatches.
  - `mem-{default,hide2}-160.alloc`: Vulkan allocations by memory type, with ggml's UMA default and with type 2 reported without `DEVICE_LOCAL`.
  - `cpu-time.json`: guest wall, user and sys time of `llama-bench` tg32 and tg160 runs (bash `time`), per token as the difference over 128 tokens, with and without the queue wait or synchronous mode and with one CPU thread.
  - `host-threads.json` with `host-threads-snap-{a,b}.txt`: utime and stime of every thread of the Android-side `crosvm_debian` process, read over adb at two moments 11.5 s apart inside a tg480 run (r3 runtime, u8 on, one CPU thread). The thread that executes the guest's Vulkan commands carries the guest process name (`llama-bench`).
- `depth/`: `llama-bench -d 0,1024` on the r4 runtime, u8 alone against u8 + decode, with `commands.json` giving the command, environment and order. Timing only; no gates ran in these processes.
- `graph/`: the experimental runtimes (`exp-patches/`, applied in the order listed in `provenance.json` on top of the r3 tree), timed with the shim's command-buffer timestamps. Every row is a 32-token and a 160-token `llama-bench` run. `gpu_ms` and `wall_ms` are per-token differences between them; `tg32` and `tg160` are `llama-bench`'s rates.
  - `skip-ablation.jsonl`: `GGML_VK_SKIP_OPS` leaves one op type unrecorded. Removing a node also removes its dependency, so later work overlaps and the savings do not add up. The rows do not measure the op's own cost.
  - `dup1-summary.jsonl`, `dup2-summary.jsonl`: `GGML_VK_DUP_OPS` records one op type twice, with a barrier between. `dup1` drifted: its middle base row is 4.5 ms slower than the first and last. `dup2` pairs each duplicate with a base run just before it, and is the one to read.
  - `attn1`, `bar1`, `dl1`, `s1`, `q6ab`: interleaved arms for the attention kernels, the compute-only barrier, device-local buffers, single submission and the Q6_K kernel. `q6ab` was rebuilt from the raw files after its printed summary failed.
- `attention/p021-test.jsonl` and `attention/p021-passes.jsonl`: [`guest/probes/p021_test.c`](../../../guest/probes/p021_test.c). Stock `mul_mat_vec_p021.comp` (subgroup-add variant) and `mul_mat_vec_p021_pvr.comp` on the same random f16 K and f32 queries. Records bitwise differences, unwritten outputs, NMSE of both against a double-precision reference, and the marginal GPU time per dispatch with a compute-only barrier. `p021-test` uses the shipped one pass per workgroup (16 positions) over nine shapes. `p021-passes` varies the passes per workgroup (1, 2, 4, 8; 16 to 128 positions) at 33 to 4096 positions.
- `kquant/kq-bench.jsonl`: `guest/kernel_bench.cpp` on ggml's Q6_K shader and the unsigned-dot Q6_K and Q4_K kernels, three rounds each. `kquant/kq-sweep.jsonl`: the unsigned-dot Q6_K and Q4_K kernels compiled with 8, 16 or 32 lanes per row (`TPR`) and 1, 2 or 4 rows per lane group (`RPS`).
- `readback/`: `check-readback` repeated for each switch combination with [`readback-rep.sh`](readback/readback-rep.sh), after one decode run of the r5 A/B failed its transfer gate (`r5-ab-decode-1/`: that run's receipt and checker output). `rep-r5.jsonl.gz` (r5, 20 runs per combination), `rep-exp-pinned.jsonl.gz` (the experimental tree with `exp-patches/pinned-fix.patch`, 30 runs) and `rep-r6.jsonl.gz` (r6, 30 runs) hold every checker line with its combination and run number. The last two files are byte-identical, since an all-pass run prints the same lines on any runtime; `summary.json` records which runtime each series ran. It also gives each runtime's `libggml-vulkan.so` hash, the environment of each combination, the failed runs and every failed case.
- `logits/logit-checks.jsonl`: every full-logit vector the experimental runtimes produced with `check-model`. It gives the NMSE against the stored CPU reference, whether the vector equals the r3 candidate (`511616a0…`), and the checker's own JSON.
- `provenance.json`: hashes of the experimental patches, the experimental runtimes' `libggml-vulkan.so` (`exp_runtime_patches` gives the patches behind `exp-pinned`), the reference vectors, the probe sources and shaders as they are now (see `probes/` above), and every file in this directory except itself and this README.

## Reading the numbers

The GPU's own clock was read from `/sys/class/devfreq/34f00000.gpu0/cur_freq` over adb. It stays at 1286 MHz for most of a decode run. Run-to-run noise is still about ±5% on `tg160`, and one arm series drifted by 15%, so only adjacent or interleaved rows are compared. The experimental runtimes carry timing knobs (`GGML_VK_SKIP_OPS`, `GGML_VK_DUP_OPS`, `GGML_VK_PWR_SINGLE_SUBMIT`) and a subgroup softmax that the final patch does not include.
